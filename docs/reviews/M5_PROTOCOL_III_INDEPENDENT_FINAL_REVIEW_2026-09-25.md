## Field, DPF, and payload algebra

`ProtocolIIIField` stores canonical values `0 <= x < 2^127−1` in `unsigned __int128`. Addition cannot overflow 128 bits for two canonical operands. Subtraction performs a conditional modular borrow. Multiplication uses four exact 64-bit limbs and folds at `2^127≡1 mod p`; inversion uses exponent `p−2` and rejects zero. Deserialize requires exactly 16 big-endian bytes and rejects `x>=p`; it never silently reduces noncanonical input. The independent double-and-add test covers 5,000 random products and boundary `0,1,p−1`, with 256 random inverses. Standalone payload `u+1` handles `u=0` and `UINT64_MAX`; packed `(key<<64|payload)+1` accepts declared key widths 1–62 and rejects overflow/out-of-width. **FIELD_ARITHMETIC_REVIEW = PASS at tested and inspected boundaries.** `ProtocolIBlock192` is not treated as H. The selected field is solely C-INSTANTIATION, not an author-selected field.

The field DPF wrapper calls native `keyGenDPF` for the tree, then computes an `F_p` leaf correction at alpha. Native `Z_(2^64)` outputs are never reinterpreted as field shares. At the point, the two native control bits differ, and the correction makes the field-share sum beta. Away from the point, the native seed/control states agree and the signed leaf values cancel to zero. `Eval` descends one branch; `FullEval` traverses the same tree to every leaf, indexed by DPF input. Generation and decode bind party, session, fingerprint, slot and domain; two separate party keys are serialized. Point and FullEval conformance includes beta `0,1,p−1`, random beta, alpha boundaries, nonpoints, party swap, malformed encodings, and FullEval-versus-single-Eval. The online bundle contains only one party's mask share, DPF key and triple shares. No complete `s_i^-1` is directly handed to either online party. **FIELD_DPF_WRAPPER_REVIEW = PASS as implementation-level functional/structural review; formal cryptographic proof = NOT_ESTABLISHED.**

P2 samples `s_i∈F_p*`, gives additive shares of `s_i` and party DPF keys for beta `s_i^-1`, and prepares field Beaver triples. R1 opens `d=z−a` and `e=s−b`; local Beaver finish yields shares of `z̃=z·s`. R2 opens `z̃`; at the matching point the locally reconstructed result is `z̃·s^-1=z`, elsewhere zero. Since `u=0` encodes as 1, a zero application payload survives this algebra. **PAYLOAD_MASK_ALGEBRA_REVIEW = PASS.**

The two-round API accepts comparison priority-key shares plus independently field-shared encoded records. Their key meanings must agree. There is no secure consistency proof or secure ring-to-field conversion; the latter cannot be replaced by plaintext test-controller reconstruction. `INPUT_CONSISTENCY_PROOF = NOT_IMPLEMENTED`; this is a documented trusted-input precondition. `RING_TO_FIELD_ADAPTER_STATUS = DEFERRED` for the two-round path. A formal proof is not a separate current acceptance requirement, but the missing adapter and its end-to-end cost remain part of the current M5 completion finding below.

## Two-round causal and process audit

Actual dependency DAG for both Fselect and Fsort:

```text
offline P2: comparison masks/edge keys, rank masks/DPFs, s shares, Beaver triples
  → online input shares released after P2 exits
  → R1 outbound: masked priority-key shares and (d,e) field opening shares
  → R1 inbound: masked keys public; local shared CmpAgg ranks and z·s shares
  → R2 outbound: masked-rank shares and z·s shares
  → R2 inbound: masked ranks and z·s public
  → local DPF Eval (Fselect) or FullEval (Fsort), field aggregation, output shares
```

`prepare_round1` returns the complete `44+40n` byte application buffer before `consume_round1` reads the peer. `prepare_round2` returns `44+24n` bytes before `open_round2` reads its peer. The owning Fselect transport (`protocol_iii_two_round_party`, lines 425–451) sends/receives exactly one frame on each of two descriptors and returns after local finalization. The independent-process Fsort path runs the same state object and two frames, then calls `consume_round2_sort` locally. No post-R2 socket send, ACK, correction, opening, or result-dependent protocol response was found. **FSELECT_TOTAL_CAUSAL_ROUNDS = 2; FSORT_TOTAL_CAUSAL_ROUNDS = 2; FSELECT_HIDDEN_THIRD_ROUND = NO; FSORT_HIDDEN_THIRD_ROUND = NO; POST_R2_PROTOCOL_FRAME_COUNT = 0.**

The process test uses `fork` followed by `execv` for P2, P0 and P1, closes unwanted descriptors per role, and gives the P2 role only offline bundle and receipt descriptors. The controller waits for successful P2 exit and both party bundle-ready events before releasing party-local input frames. Exec gives online parties fresh address spaces, so they do not inherit dealer full-secret runtime state. P2 has no online-input, R1, R2, or correction descriptor. **PROCESS_ISOLATION_REVIEW = PASS; P2_ONLINE_SILENCE_REVIEW = PASS.**

The process harness hashes the **entire same outbound byte vector** immediately after each `prepare_round*`. P1 receives first, checks that vector's digest, and then sends it; P0 sends first and checks after receive. Ordered events verify this for R1/R2. This supports outbound independence from same-round inbound, beyond a `rounds=2` metric. Final field output shares are formed by `consume_round2*` before the party sends a TEST_ONLY report to the controller. The controller's one-byte release ACK only keeps child descriptors alive until results are collected and is not read into protocol state. **RESULT_COLLECTION_NOT_PROTOCOL_ROUND = YES.**

Fsort calls shared CmpAgg once and one `FullEval` per item/party after R2; its target loop only indexes local field leaves and performs field additions/multiplications. It never reruns network Fselect per target. With `m_i=rank_i+r_i`, FullEval index `x=(m_i−t) mod 2^r` equals alpha `r_i` iff `rank_i=t`; therefore exactly one honest item contributes `s_i^-1` to each logical slot. The result vector has `logical_n` entries. For n=3,5,20 the domains are 4,8,32, but padded targets are not emitted; honest ranks occupy `[0,n)`. This is C-INSTANTIATION relative to the paper's `Z_n`. **FSORT_FULLEVAL_REVIEW = PASS; NON_POWER_OF_TWO_REVIEW = PASS within tested honest-input scope.**

## Independent communication and local-work derivation

The separate H1 paper-cost specification was committed before the benchmark work (`M5_PROTOCOL_III_H1_PAPER_COST_SPEC_2026-09-25.md`); this review also checked PDF page 10 directly. Unoptimized Theorem 4.2 for both online parties states `6nℓ' + 2nr + 4np` logical bits, `ℓ'+p=ceil(log2|H|)`, two rounds, `2*C(n,2)` DCF.Eval and `2n` DPF.Eval. Here `ceil(log2|H|)=127`, so the assumption-compatible field-capacity substitution is `p=127−ℓ'`. It is not a claim that the application payload itself uses that many bits; the packed application payload is 64 bits. The paper base formula becomes `2nℓ' + 2nr + 4n·127`.

I derived the implementation from `prepare_round1/2` rather than the metrics fields: per party R1 has `n` comparison shares of logical width `ℓ'` and `2n` field openings of 127 bits; per party R2 has `n` rank shares of width `r` and `n` masked field records of 127 bits. Across both parties: `R1=2n(ℓ'+254)`, `R2=2n(r+127)`, total `2nℓ'+2nr+6n·127`. **Symbolic delta = 254n bits**, a third field value per item per party relative to the unoptimized theorem substitution. It is protocol data, not metadata. Fselect and Fsort use the same messages.
