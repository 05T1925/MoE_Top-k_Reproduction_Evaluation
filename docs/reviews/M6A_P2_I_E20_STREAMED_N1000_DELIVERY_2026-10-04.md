## 2. 新材料形式与安全边界

`E20_STREAM_AEAD_V1` 保留旧内存入口，从 n=1000 起另设有界路径。可信、离线、非合谋 T 在任何在线输入出现前，为共享节点 mask 和每一轮全部 `C(D,2)` 个 canonical 端点对生成两方 uCMP key，逐条经分方私有 socket 交付；T 在线静默。每方独立 OS UID 的 0700 目录/0600 文件内保存本方 AES-256-GCM 固定记录，256 位随机盘密钥只驻留该次进程内存。文件头、party/session/fingerprint/n/D/K/r/比较宽度/material ID 与记录 slot/轮次/端点一并绑定为 AEAD AAD，唯一 slot nonce 与 tag 检验篡改。预分配全长、写入、`fdatasync`、原子发布及目录 `fsync` 后才 ready；首次输入依赖消息之前以持久 `O_EXCL` claim 领取整份，崩溃即消耗。在线仅按活跃边计算偏移并读取、认证、解码；不会请求 T、只预发活跃边或用文件轮询替代同步。在线文件访问形态可被可信宿主观察，公开活跃图本身已在当前项目双方泄露合同内；多 key 联合模拟尚未证明，`AUTHOR_EXACT=NOT_PROVEN`。

`E20_CLIQUE_SEALED_V1` 使用同一已审查的分方封存/领取路径在离线预发 `C(D,2)` 条比较材料；原 Protocol I shuffle 保持真实 EMP OT 与全对全比较。T 额外生成但未用于该基线的 O(D) AAV86 状态计入离线时间和 ready 材料；因此此标签是明确的新低内存基线形式，不能代替 E15–E17 旧基线标签。两路径都按 signed Q20.12、score 降序及 original index 升序稳定同分，输出原输入顺序 XOR Top-K bit-mask；secure 路径不重构比较位、rank、index 或 mask。

完整性由 AEAD、私有完整 T→party 通道、各方 OS 身份隔离和可信宿主假设共同支撑；SHA-256 仅用于仓库外原始证据文件的事后核验，不称作材料认证。外层标签也不能证明 uCMP key 与共享节点 mask 的数学关联，此关联仍依赖可信 T 并由 TEST_ONLY dealer 一致性检查补充。半诚实双方及不合谋 T、独立随机性、单 key DCF 假设与已登记泄露合同均为**条件性**，没有声称论文作者精确实现。

## 3. 验证与测量口径

先在小 D 核对旧/新材料代数、canonical slot/ID、消息相位和最终 mask，再依次执行 conformance、冻结 oracle differential、独立 T/P0/P1 进程 E2E。故障测试包括错误 party/session/端点/轮次、同规格 ciphertext 交换、文件截断/篡改、重放/重复领取、T 关闭或静默、peer 故障及领取后进程中断。n=1000、K=80、r=2–5 的固定输入 differential 与三进程完整入口另逐档运行。基线 n=1000 独立通过完整入口 oracle，不能用 n=256 的旧基线替代。

正式测量沿用 E15 计时合同：离线从启动角色前至 T 退出和双方 ready，包含**全池** keygen、交付、AEAD 写盘和同步；在线取双方 secure 入口耗时较大者，含首次 claim、活跃边读取/认证/解码；每次 total 先相加再统计。ready 材料有效载荷按经验证固定布局计，实际密文文件大小、进程 RSS、预算、C: 物理余量分别列示。双方 sent/received 逐次守恒，完整入口 oracle 与恰 K 位检查在计时外。网络为同主机真实 TCP，经 `netem` 分别模拟 LAN 0.5 ms/1000 Mbit 和 WAN 25 ms/100 Mbit，逐批保存校准；这不是异机实网结论。每档 1 预热、5 正式，每次 fresh 全池和一次性 claim；AAV86 与全对全路线用同一输入种子/摘要配对。

资源监视独立于 WSL，直接采样 Windows 物理可用量、Page Reads/Writes、vmmem 及 C: **物理**盘空余；WSL `/tmp` 虚拟空余不用作放行依据。WSL 运行时 swap=0，RLIMIT_AS=1 GiB/进程，Release/EMP-ON、GCC 13.3。曾在 2 GiB/1 GiB WSL 配置观察宿主压力并中止部分批次；原始失败、未完成运行与配置变化单独保留，不纳入任何正式中位数。512 MiB 临时尝试在启动后仅余约 45 MiB WSL 内存，未进行协议测量。最终批次是否可纳入，以逐次宿主资源轨迹、Linux PSI、exit、完整 oracle 和网络门综合判定，不凭脚本 PASS 单独追认。

这些是 E20 新材料形式的跨规模观察，不能与 E17 内存池中位数拼接。`n=10⁴/10⁵/10⁶` 每个 r 的 `D`、`slots`、比较宽度、密文记录/文件和本机盘比较，由 checked uint64 计算，完整见[逐配置状态 CSV](../reproduction/M6A_P2_I_E20_CONFIGURATION_STATUS_2026-10-04.csv)及仓库外 `e20_stream_capacity_final_v2.csv`。最小 n10⁴/r2 已需**两方密文文件 661,921,431,712 B**，超过 C: 64,366,927,872 B；n10⁵/r2 为 44,839,116,472,480 B，n10⁶/r2 为 3,028,052,135,116,960 B，其余 r 更大。实际调用 12 次 `bench-stream` 入口均 exit 1、报 `E20 stream benchmark shape`，这是**真实首门**；即使移除此门，secure store 的 `n≤1000` 门和物理盘不足仍阻止 keygen。12 档均为 `RESOURCE_INFEASIBLE/PRECHECK_REJECTED`，九指标、实际峰值与运行时间 `NOT_MEASURED`。v1 容量草稿曾将第二道 store 门误写作首门，原件保留审计但**以 v2 为准**。

受控试验留下三类独立失败而不进入正式统计：(1) 早期 2 GiB WSL 配置下 r5 运行遭宿主高分页和低内存而中止，保存当刻资源、未完成日志、实际文件占用元数据；(2) 1 GiB WSL 的首批 WAN r2 在宿主可用量降至 274,456,576 B 时由控制器 SIGINT 中止，exit 1，rep4 日志不等于完整 JSONL，整批排除；(3) 512 MiB WSL 尝试启动后仅约 45 MiB 可用，**没有启动协议测试**。768 MiB 正式批次完成后，旧 Protocol III 全套回归在其 n256 用例触发 Linux OOM killer（内核记录 PID/anon RSS）；该环境问题只影响无关回归，不回填协议九指标。暂调至 1 GiB、swap=0 后同一已构建旧测试完整通过，再恢复原 WSL 配置。所有旧失败原件和宿主状态均在独立 E20 仓库外目录与哈希索引中。
