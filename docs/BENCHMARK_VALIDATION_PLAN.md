## 1. 验收范围与顺序

### 1.1 四个验收节点

| 节点 | 对象 | 主要目的 | 前置条件 |
| --- | --- | --- | --- |
| V1 | Protocol I 精确三轮核心 | 核验论文成本、实际通信与接口边界 | 实现、正确性及消息审计通过 |
| V2 | Protocol III 精确两轮核心 | 核验压缩核心成本及适配开销 | V1 交接完成，M5 实现与审计通过 |
| V3 | I+AAV86、III+AAV86 | 完成两种升级的全部适用性能指标 | V1、V2 及基础接口交接完成 |
| V4 | I+BB90+DCF、III+BB90+DCF | 完成两种组合的全部适用性能指标 | V3 完整性能验收完成 |

执行顺序：

```text
V1 → 接口交接 → V2 → 基础接口交接 → V3 → V4 → M7 汇总
```

资料核对、实验脚本设计和失败用例可以提前开展。V3 未完成前，不推进 V4 的依赖实现和正式实验。

### 1.2 两类验收的区别

V1、V2 是通信核验门，重点验证：

- 论文公式与当前功能是否对应；
- 消息结构与实际发送量是否对应；
- 核心、适配和封装差异是否可解释；
- 下一阶段能否复用可信接口和计量。

V3、V4 是完整性能验收，必须同时覆盖：

- 正确性；
- 离线时间和材料；
- 在线时间和通信；
- 因果轮数；
- PRG 与比较边；
- LAN/WAN；
- 完整参数矩阵及失败配置；
- 可复跑的逐次数据和汇总报告。

V1、V2 不以先跑完所有超大规模全对全配置为前提。V3、V4 不能只完成通信测量就标记为完整性能验收。

### 1.3 结论边界

通信一致性、功能正确性和安全性分别验收。

- 数量级接近不能单独证明论文、代码或安全性正确。
- 数量级不同不能未经分析直接判定论文错误。
- 轮数相同不能代替消息依赖审计。
- 输出正确不能掩盖额外泄露或在线 Dealer。
- 理论估算不能填入实测字段。

## 2. 被测对象与统一语义

### 2.1 正式目标方案

1. Protocol I。
2. Protocol III。
3. Protocol I+AAV86。
4. Protocol III+AAV86。
5. Protocol I+BB90+DCF。
6. Protocol III+BB90+DCF。

每个实际实现必须记录独立标签、revision、输入边界、输出边界和安全模型。规划名称不能作为已完成证明。

工程对照另列：

- Protocol I 四轮核心、raw-score 八轮路径；
- Protocol III 三轮核心；
- Protocol III raw-score 五轮路径。

CipherGPT 不纳入本轮实验。

### 2.2 输入输出

沿用冻结契约：

- 输入为 n 个 32 位二补码 signed fixed-point score 算术共享；
- 小数位数为 12；
- `raw=(x0+x1) mod 2^32`；
- score 降序、original index 升序；
- 最高优先级 rank 为 0；
- 输出为原始输入顺序下长度 n 的秘密共享 Top-K bit-mask；
- 重构后每位为 0/1，且恰有 K 位为 1。

各方案使用同一 oracle。测试重构与明文校验只存在于隔离的 TEST_ONLY 路径，不进入 secure runtime。

BB90+DCF 必须验证完整阈值选择与成员判断，不能只验证第 K 大 score。重复值情况下必须保持稳定同分规则，不能用简单 `score >= 阈值` 代替精确 Top-K。

## 3. 参数与输入矩阵

### 3.1 正确性矩阵

正式测量前覆盖：

- 随机输入；
- 重复 score；
- 全相等；
- 正负混合；
- 量化值和位宽边界；
- `K=1`、`K=n`；
- 非二次幂 n；
- 最小有效规模；
- 非法 n、K 和输入长度；
- package/session/fingerprint 错误；
- 截断、超时和 peer 提前退出；
- 一次性材料重复使用。

每个合法用例检查 mask 长度、二值性、基数和与 oracle 的逐位一致性。

异常测试与性能实验分开。错误输入的拒绝时间不能混入正常运行性能表。

### 3.2 V1、V2 通信核验参数

至少包含：

| 配置类型 | 要求 |
| --- | --- |
| 小规模边界 | 覆盖最小规模、重复值、全相等、K 边界和非二次幂 |
| 固定基线 | `(128,2)`、`(128,8)`、`(256,2)`、`(256,8)` |
| 增长检查 | 在资源允许范围增加 n，核查线性项、封装项和 K 相关项 |
| 论文对照 | 按所选定理功能和参数建立单独对照配置或参数映射 |

增长检查的具体点在运行清单中预先记录。若增加的规模无法运行，应记录原因，不能用外推值替代。

论文使用不同输入位宽或输出功能时，不修改冻结应用语义来强行匹配表格。需要独立论文核心配置时，使用明确标签，与统一 raw-score→mask 配置分栏。

### 3.3 V3、V4 完整性能矩阵

| n | K | AAV86 迭代 r |
| --- | --- | --- |
| 128、256 | 2、8 | 2、3、4、5 |
| `10^3`、`10^4`、`10^5`、`10^6` | 80 | 2、3、4、5 |

要求：

- V3 两种路线均覆盖适用的 `(n,K,r)` 组合。
- V4 两种路线沿用 `(n,K)` 矩阵。
- BB90 参数依据采用算法单独固定，不直接复用 `aav86_iterations_r`。
- 参数不适用必须给出算法依据，不能因实现尚未支持就标为不适用。
- 所有矩阵配置均保留处理状态，不静默删除困难点。

### 3.4 数据与随机性

基础随机量化整数分布保持：

```text
[-32*2^12, 32*2^12]，端点包含
```

其他分布单独命名，不替换基础配置。

分别记录：

- 输入种子或输入标识；
- 算法种子；
- 重复编号；
- 实际图规模及迭代参数。

同一比较组使用相同输入。相同算法的 I/III 两种路线采用对应的算法种子和配置，方便比较实际工作量。

不同算法不要求因种子编号相同而生成相同内部行为。

密码学掩码、密钥和一次性材料每次运行重新生成。预热与正式运行不得重复消费材料，不在报告中保存秘密材料或可恢复秘密随机性的记录。

## 4. 环境与运行准备

### 4.1 环境清单

每个正式实验批次记录：

- Git revision、工作树是否有未提交改动；
- 编译器、版本、flags 和 build type；
- 依赖版本及相关构建选项；
- CPU、核心/线程、内存、OS；
- 每方部署位置和进程拓扑；
- 线程数及并发策略；
- 网络拓扑、带宽、RTT；
- 资源限制、超时和实验命令。

正式对比优先使用相同优化配置。Debug 正确性结果不能直接与另一方案的优化构建做性能排名。

### 4.2 LAN/WAN

LAN、WAN 的带宽和 RTT 必须在实验前固定并记录实测值，不能只填写“LAN”或“WAN”。

网络模拟可使用，但必须注明：

- 模拟工具和配置；
- 限制作用于哪些连接；
- 实测 RTT 和吞吐；
- 是否存在本机 loopback 或共享主机影响。

论文网络配置可作为独立对照目标，不视为已经测得的本地环境。

两方不得因使用不同机器、线程数或网络配置而被无说明地放入同一速度比较。

### 4.3 运行次数与调度

每个正式配置：

```text
预热 1 次
正式运行 5 次
```

- 预热结果不进入统计。
- 保存五次正式运行的全部结果。
- 固定并记录输入/算法种子安排。
- 避免不同方案争用同一机器资源。
- 若采用并发或批处理，单独记录并发度和实例数。
- 随机算法保留所有运行结果，不能只选工作量最小的种子。

发生环境故障需要重跑时，保留原失败记录和重跑原因，不静默替换。

## 5. 计量边界

### 5.1 必须区分的范围

```text
离线预处理
raw-score 输入适配
论文核心或组合核心
输出与 mask 适配
测试和报告辅助工作
```

主比较使用 raw-score 输入到原顺序共享 mask 完成的完整安全路径。

论文核验单独提供功能和参数一致的核心结果。不能把适配成本从主比较删除，也不能直接将其全部归为论文成本。

### 5.2 离线时间

`offline_time_ms` 覆盖本次在线执行实际需要的全部预处理。

明确记录是否包括：

- Dealer/离线进程启动；
- 材料生成；
- 序列化；
- 分发；
- 接收完成及离线屏障。

使用缓存、批量材料或跨实例摊销时，记录生成批次、实际消费量和摊销规则。不能把预先生成的材料计为零成本。

论文成本没有包含的工程生命周期开销单独解释。历史结果保留原起止边界。

### 5.3 在线时间

正式主指标 `online_time_ms` 的目标边界为：

```text
在线方输入和离线材料就绪
  → 开始必要的安全输入适配与协议执行
  → 两方均完成原顺序共享 mask
```

按完整执行的关键路径统计，不把两方耗时相加作为端到端延迟。

必须说明跨进程计时方式。不能直接相减未经同步的两台主机时间戳。

以下辅助工作原则上与主协议分开记录：

- 测试控制器分发输入；
- oracle 重构与检查；
- report 收集；
- 测试 acknowledgement；
- 子进程清理。

若 runner 只能提供包含这些步骤的包围时间，应准确标记其边界，并补充协议范围计时；不能将包围时间直接冒充纯协议时间。

协议本身必需的同步和通信必须计入，不能因为实现位于控制层就排除。

### 5.4 离线材料

`offline_material_total_bits` 表示实际提供给在线执行的全部预处理材料。

包括适用的：

- DCF/DPF keys；
- 掩码共享；
- 乘法相关材料；
- shuffle/OT 相关材料；
- 索引、路由和共享转换材料。

逻辑密钥大小、内存对象大小、序列化材料大小和传输封装大小分别说明，不能混用。

离线传输封装可另设诊断计数；不得把在线补发材料隐藏到“离线材料”字段。

### 5.5 在线通信

必需字段：

```text
online_comm_total_bits
online_comm_per_party_bits
每方 sent_bits
每方 received_bits
```

定义：

```text
online_comm_total_bits = 所有在线方 sent_bits 之和

online_comm_per_party_bits
    = online_comm_total_bits / 在线方数量
```

received 用于核查接收完整性，不再加入 total。

报告中区分：

- 协议有效载荷；
- 应用层帧头、序列化和必要控制消息；
- 网络链路抓包数据，如另行测量。

主字段应明确计数层。应用层实际发送字节不能被称为已测得 TCP/IP 链路总流量；内核重传等若未单独测量，不臆造其成本。

分阶段计数应与总量对账。跨阶段合并发送的消息只计一次，并说明分配规则。

测试报告和控制流若不属于协议，使用独立计数；不能混入论文核心，也不能排除真正必要的协议消息。

### 5.6 因果轮数

`online_rounds` 根据消息依赖确定。

- 并行、相互独立的消息可以属于同一轮。
- 后续消息依赖上一轮接收结果时，不能因合并函数或批量发送而删轮。
- `send()` 次数、帧数和 socket 调用次数不等于轮数。
- input adapter、core、mask adapter 分别说明。
- 存在重叠执行时，以真实依赖图给出总轮数。

轮数记录必须附阶段表，不能只输出硬编码常量而没有执行路径证据。

## 6. 统一指标与扩展计数

### 6.1 主指标

| 字段 | 单位 |
| --- | --- |
| `offline_time_ms` | ms |
| `offline_material_total_bits` | bits |
| `online_time_ms` | ms |
| `online_comm_total_bits` | bits |
| `online_comm_per_party_bits` | bits |
| `online_rounds` | rounds |
| `online_prg_calls_total` | calls |
| `comparison_edges_total` | comparisons |
| `total_time_ms` | ms |

其中：

```text
total_time_ms = offline_time_ms + online_time_ms
```

只有对应时间均已测得且边界一致时才派生 total，不用缺失值或零填补。

### 6.2 PRG 与原语计数

`online_prg_calls_total` 统计所有在线方实际执行的长度倍增 PRG 调用。

必须说明：

- 计数位置与覆盖的代码路径；
- 是否覆盖 DCF、DPF、shuffle 等实际在线调用；
- 批量/SIMD 求值的归一化方式；
- half-evaluation 或其他优化的实际计数方式。

AES 调用、DCF.Eval、DPF.Eval 和 PRG 调用不是同一单位。可以并列记录，但不能未经定义直接等同。

由理论密钥深度或公式推算的 PRG 数只放在理论字段，不能填入实测字段。

并行计数不得丢失更新或重复汇总。计数器需要用可人工核对的小实例验证。

### 6.3 比较边

`comparison_edges_total` 记录实际执行的无序比较边。

- 一条边由两方分别求值，不因此记为两条边。
- 同一位置对在不同算法步骤重新比较，按实际执行次数计入。
- 比较边与 DCF 调用分别统计。
- logical/padded 范围必须明确。

### 6.4 AAV86

每次记录：

- `r`；
- 实际迭代与图参数；
- `e_A(n,r)`：各迭代比较边之和；
- `v_A(n,r)`：各迭代参与节点数之和；
- 每轮通信、材料、DCF/uCMP 和 PRG；
- 路由与 mask 适配成本。

实际计数与理论期望值分别列出。单次随机图的边数不能冒充期望复杂度。

### 6.5 BB90+DCF

分开记录：

- BB90 选择阶段；
- 最终 DCF 成员选择阶段；
- 路由、逆映射和共享转换；
- 完整总路径。

记录 BB90 参数、实际迭代、种子、节点/边数及算法保证。

最终 DCF 调用不应被隐藏在 BB90 图计数中；若另计入总体比较统计，必须明确分类和汇总关系。

## 7. V1：Protocol I 通信核验

### 7.1 前置条件

- 精确核心候选已完成 conformance、差分和独立进程 E2E；
- 同置换 public masked-list 与 GRank 材料条件已审计；
- Dealer 输入无关、在线静默；
- 三轮核心的消息依赖明确；
- raw-score 和 mask 适配边界明确。

### 7.2 方法

1. 固定 revision、标签和测试配置。
2. 列出 Theorem 4.1 的适用功能、参数与公式。
3. 建立论文参数到实现参数的映射。
4. 逐消息推导实际有效载荷与序列化长度。
5. 实测分方、分阶段发送和接收量。
6. 对照核心、适配及封装差异。
7. 使用增长配置验证消息规模趋势。
8. 修正发现的问题后重跑受影响配置。

重点检查：

- 是否多出独立 masked-key exchange；
- shuffle 与 GRank 掩码是否真正关联；
- padding、priority-key 位宽和 payload 是否扩大；
- rank reveal 与 reverse mask 是否正确分类；
- 三轮核心是否通过减少必要步骤或扩大公开信息实现。

### 7.3 交付物

- 论文公式及参数映射；
- 消息与长度清单；
- 原始分方计数；
- 逐阶段差异表；
- 正确性、轮数和安全审计；
- 复跑命令；
- M2→M5 接口交接所需计量说明。

### 7.4 通过条件

计数可复算、消息可解释、关键差异已定位，且正确性与安全条件仍成立。不能仅凭“接近论文数量级”通过。

## 8. V2：Protocol III 通信核验

### 8.1 前置条件

- V1 和 M2→M5 交接完成；
- M5 域、非零编码和 DPF 兼容性已验证；
- 两轮核心、差分和独立进程 E2E 通过；
- 输入及 mask 适配完整。

### 8.2 方法

沿用 V1 的三层对账，主要对照 Theorem 4.2。

重点检查：

- 是否满足域与非零 payload 条件；
- 共用掩码优化是否实际采用；
- 单个顺序统计量与 Top-K mask 的差异；
- DPF 求值次数、目标 rank 数及本地计算变化；
- 域转换、payload 编码和 mask 输出通信；
- 是否错误沿用 M3 环上最低位转换结论；
- 是否以单位 payload 特化冒充完整压缩；
- 是否把 M3 的历史包围时间当作可比核心时间。

### 8.3 交付物

除 V1 同类材料外，还提供：

- M3/M5 功能与开销对照；
- 代数表示及优化清单；
- K 变化对计算、材料和通信的实际影响；
- 进入 M6A 的基础计量接口说明。

### 8.4 通过条件

论文前提、两轮消息依赖和统一输出均满足；实测与实现消息一致；论文差异已解释；交叉复跑通过。

## 9. V3：AAV86 完整性能验收

## 11. 统计与差异解释

### 11.1 汇总方法

对正式运行保留逐次原始值，并报告：

```text
median
min
max
```

- 先对每次运行派生 total/per-party，再做统计。
- 不用各阶段 median 之和冒充总时间 median。
- 不用两方耗时之和表示在线延迟。
- 随机工作量变化时，边数、节点数和运行时间一并保留。
- 比较组若使用固定与变化种子两种实验，分别标记，不混合汇总。

### 11.2 差异分类

每个主要差异归入明确类别：

| 类别 | 示例 |
| --- | --- |
| 功能差异 | 单个选择与完整 Top-K mask |
| 参数差异 | 位宽、payload、logical/padded n |
| 协议差异 | 额外交互、不同路由或未采用优化 |
| 表示差异 | ring/field、序列化和字节对齐 |
| 工程封装 | 帧头、必要控制消息 |
| 计量问题 | 重复累加、计数范围错误 |
| 环境差异 | RTT、带宽、线程、编译选项 |
| 未解释 | 暂无证据支持的偏差 |

未解释项保留为问题，不归入笼统“工程开销”后宣布通过。

### 11.3 计数自检

使用小实例验证：

- 序列化长度与实际发送计数对应；
- 一方发送与另一方接收在同一范围内对应；
- 阶段计数与总量对应；
- total/per-party 派生正确；
- 比较边不因两方求值重复计算；
- PRG 计数无遗漏、重复或并发丢失；
- core 轮数与完整消息表一致。

## 14. 总体验收原则

- V1、V2 分别通过通信核验后，才能完成对应接口交接。
- V3、V4 必须分别完成两种路线的完整性能验收。

- 成功运行而缺少必需指标，不标为全部指标完成。
- 理论、历史、当前实测和未测始终分开。
- 未解释的关键通信或协议差异不能被数量级结论覆盖。
