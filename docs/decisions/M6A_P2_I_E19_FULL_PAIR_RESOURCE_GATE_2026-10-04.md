# M6A-P2-I-E19：全两两预发路线资源门（2026-10-04）

## 判定及证据级别

E19 从 E18 `57e239ee820a4208ac606663d877803f0b692206` 单独分支。E18 draft PR #28 的 head、E15–E17 冻结原件和主工作区均保持原状。本决策只核算当前全两两预发、T 在线静默、双方在线消费活跃边的**现有**内存材料形式；没有调整 secure 源码、测试输入、材料布局、消息、泄露或 E15 计时边界。`n=1000,K=80,r=2..5` 与更大 12 档均不准进入 keygen；状态为 `RESOURCE_INFEASIBLE_CURRENT_IMPL / PRECHECK_REJECTED`，完整协议九指标、实际峰值与 keygen 耗时均为 `NOT_MEASURED`。这不是性能失败、加速/减速结论，也不是所有资源架构的不可行性证明。

证据分四级：C++ 入口原始输出是**实际执行的预检**；逐字段公式是**当前固定布局的 checked 推导**；Dealer `8×包+64 MiB` 及 `3×` 是**准入预算**；完整协议九指标及实际峰值是**未测**。特别不能把 `/tmp` 的 WSL 虚拟文件系统空闲数写成宿主物理盘余量。

## Checked 容量与真实首门

源码 `VFSS/src/moe_topk/protocol_i_aav86_small.cpp` 的 64 位检查加/乘给出：`D=max(2,next_pow2(n))`，`b=33+log2(D)`，`pairs=C(D,2)`，`slots=r×pairs`，每方串行包 `P=114+D×(1844+8r)+slots×(81+24b)` B，双方包 `2P`；Dealer 准入预算 `B=8P+64 MiB`，既有可用内存要求 `3B`。材料 ID `3+slots` 在这 16 档均未溢出 `uint64_t`。脚本独立以 Python 检查 64 位运算，和新编译 C++ 输出的所有 16 行 `D/slots/P` 一致。T 单方有效载荷下界 `L=2D×856+slots×(24b+24)+D×(48+8r)` 是固定布局推导；当前 E2E 的 T 同时持有两方 pool 和两方序列化字节，故保守同时存活下界 `2(P+L)`，Party 在收到包并解码时的下界为 `P+L`。它们不是 RSS 观测，未计 allocator、DCF 暂存或操作系统开销。

`n=1000,r=2` 的 `2P` 单项即超过当刻宿主**可用**内存；`3B=28,229,249,712 B` 超过宿主**全部** 16,779,862,016 B。r=3..5 分别为 42,220,550,832 / 56,211,851,952 / 70,203,153,072 B。r=4/5 的 T 保守下界还超过 WSL 的物理内存总量，r=3..5 的 Party `P+L` 超过既有 3 GiB 地址空间限额；r=2 下界虽低于 3 GiB，仍没有 allocator/协议计算余量。WSL 2 GiB swap 不替代物理内存；靠严重换页完成的运行不能作为正常性能。n1000 两方包可容于 C: 物理盘，但当前材料不是受保护的磁盘驻留架构，磁盘余量不能换算成已实现的流式 T/P 内存。

对 n=10⁴、10⁵、10⁶ 的逐 r 精确整数、物理盘比较、下界及状态，见仓库外 `e19_configuration_status_v2.csv` 和 SHA 索引。最小 `n=10⁴,r=2` 已是 `D=16384`、每方 268,419,072 槽、`P=324,549,132,402 B`、`2P=649,098,264,804 B`、`B=2,596,460,168,080 B`，超 C: 物理余量；更大 11 档单调增加。n≥10⁴ 的当前包长度还超过 32 位承载范围。16 档的原程序**实际首门**都是 `HARD_CAP_D_GT_256`；若只移除这道门，下一道现有门是 `PACKAGE_GT_192_MIB`，随后 `B>2 GiB`、可用内存及进程限额。`validate_config` 的现有 `n≤256`、T/P 收包门（AAV86 192 MiB、基线 64 MiB）、串行 `Writer` 192 MiB 限额和正式 benchmark 的形状限定也是独立阻碍。不能只把常量调大后宣称 n1000 已获准。

新编译 C++ `moe_topk_m6a10_aav86_metrics_conformance_test` 在 3 GiB `RLIMIT_AS` 下实际打印 16 行拒绝，未启动 keygen。EMP-ON 全对全基线的 `bench 1000/10000/100000/1000000 80 ...` 各实际退出 1，首门 `E16 baseline benchmark shape`（只允许 n128/256、K2/8）；基线 n1000 的固定材料有效载荷单方约 554,868,736 B，已超过当前 64 MiB 收包限额，故不是仅修改形状即可配对。基线未测，也不以 AAV86 单路线数字形成胜负。

## 后续可重新申请的实现门

若要重试 n1000，须先有经审查的材料驻留/分配/传输方案，明确全量端点对仍由 T **离线预发**、T 在线静默、两方只在线消费活跃边；同时说明加密保护、配置和材料 ID 绑定、一次性领取、错误关闭、磁盘占用、进程峰值及时间成本。磁盘流式材料是**新实现标签和安全/计时合同**，需按新 revision 完成 conformance→冻结 oracle differential→独立 T/P0/P1 E2E，覆盖 signed Q20.12、原下标稳定同分、padding、K 边界、恰 K 位、复用/篡改/peer 故障，再按 E15 合同做 fresh 材料、1 预热+5 正式的配对 LAN/WAN。固定 M 或重绑定 key 目前 `UNPROVEN`；不能把抽样、只生成活跃边、在线补发或明文 key 文件轮询当作当前全池路线。既有可信非合谋 T、私有完整通道、独立随机性、单 key DCF 隐私和所列 PRG/泄露假设保持**条件性**，联合多 key 模拟未证明，`AUTHOR_EXACT=NOT_PROVEN`。
