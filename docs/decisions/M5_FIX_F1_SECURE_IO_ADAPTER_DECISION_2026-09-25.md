# M5-FIX-F1 secure standard-input / standard-mask decision

Date: 2026-09-25. Base: `3904afb461597d6a142f3d534c6686fb377bb4ec`, branch `feat/m5-protocol-iii-two-round`. This decision describes the uncommitted F1 worktree; it does not sign off G3 or close M5.

## Authority and scope

[H2 finding F1](../reviews/M5_PROTOCOL_III_INDEPENDENT_FINAL_REVIEW_2026-09-25.md) requires a secure standard input/output path and its *full* cost, not merely the already verified field Fselect/Fsort core. [M5→M6A handoff](../handoffs/M5_PROTOCOL_III_TO_M6A_HANDOFF_2026-09-25.md) records the open adapter and receiver gate. The current user instruction explicitly permits a narrower standard-mask path that **does not need a secret field record**, provided it securely produces the unified original-order mask and leaves the field Fselect/Fsort APIs unchanged. This is a new **project C-INSTANTIATION**; it is not the paper's general field-valued Fselect, a field→bit conversion, or an author-exact transcript.

Standard input: each online party holds `logical_n` `uint32_t` additive shares in `Z_(2^32)` of signed two's-complement Q20.12 words (12 fraction bits; raw signed range `[-2^31,2^31-1]`). Public `logical_n >= 2`, `1 <= K <= logical_n`, party, session, fingerprint, material ID and widths are bound. The `n=1` case is rejected by this F1 API; large-n throughput is not claimed by these small conformance runs. Standard output: each party holds `logical_n` `uint8_t` XOR bit shares in **original input order**. Reconstruction is `mask[i]=1` iff the item is among stable Top-K, with exactly K ones, score DESC and original index ASC. Padding never appears in the output.

## Algebra, causality, and privacy

Let `p=padded_n`, `n=logical_n`, `r=ceil(log2 n)`, `ell'=33+index_bits`. Existing score conversion computes priority-key shares with `(UINT32_MAX-(raw_score XOR 0x80000000))<<index_bits | original_index`. Padded positions receive the minimum signed score and larger indices. Shared CmpAgg produces logical original-order rank shares in `Z_(2^r)`, rank 0 highest; no rank is opened.

For item `i`, the routing dealer chooses `r_rank[i]`, shares it, and sends each party one native 64-bit-output DPF key for `f_(r_rank[i],1)`. Online parties open only `m_i=(rank_i+r_rank[i]) mod 2^r`. For each public target `t in [0,K)`, local DPF evaluation at `(m_i-t) mod 2^r` yields `a_(i,t),b_(i,t)` with `(a+b) mod 2^64 = [rank_i=t]`. Each party sums its K local shares in `Z_(2^64)` and takes the low bit. The map `Z_(2^64)→Z_2`, `x↦x mod 2`, is an additive homomorphism, so the XOR of these two low bits is `[rank_i<K]`. For honest stable ranks, exactly K original positions are selected. This proof **does not apply** to the odd-prime field shares of general Fselect/Fsort.

Causal DAG: score-share input → carry outbound/peer read → sign outbound/peer read → padded priority-key shares → GRank masked-key outbound/peer read → logical rank shares → routing masked-rank outbound/peer read → local DPF evaluation and local parity. Every outbound is computed before its same-stage peer read. There is no output-adapter message or P2 online message. The **full standard path is four online causal rounds**; the standalone general field Fselect/Fsort core remains two rounds. A four-round standard path must never be advertised as a two-round raw-score pipeline.

P0/P1 see their own score shares, party-local one-shot material, masked comparison keys, masked ranks, and their own final mask shares. They do not receive raw scores, raw ranks, peer materials, selected indices, or a public mask. P2 has the full input-independent preprocessing randomness, sends each party's bundle and exits **before input-dependent online execution** in the process harness. The test controller alone knows clear scores and reconstructs the oracle; P0/P1 receive neither the controller's private input-share RNG seed nor the dealer's private RNG seed. The new mask route has no `s_payload`, field record or field→bit conversion.

## Material, failure and evidence boundary

The F1 bundle is versioned and binds party, session, fingerprint, material ID, logical/padded n, K and widths. It contains score carry/sign uCMP/DCF material, GRank node/edge material, rank-mask shares and one native DPF key per logical item. Application metadata and score materials use explicit big-endian encoding; the existing M2 edge package codec is reused. The embedded native DPF tail is **same-build/same-architecture**, not portable canonical key encoding. Truncation, trailing bytes, wrong version, party, shape, width, material ID, session or fingerprint are rejected before online input. The aggregate material sets `started` before the first online frame: success and partial failure both make the object non-reusable. Material-ID uniqueness across separate fresh processes remains controller-managed; there is no persistent replay database or malicious-party proof.

The test dealer samples 128 private seed bits inside P2 via OS `getrandom`, then expands them with the bundled AES PRNG for masks and separate native FSS PRNG seeds; public IDs are sampled independently of the controller's private fixed input-share seed. The process harness uses `fork+exec`, sockets and no file polling or online dealer. These tests are functional/security-boundary evidence under the existing semi-honest native FSS assumptions; they are not a formal DPF security proof.

## Cost contract and limits

Across both online parties, logical online bits are: input carry `4p·34`, input sign `4p·34`, GRank `2n·ell'`, routing `2n·r`, output adapter `0`. Total `272p+2n(ell'+r)`. The current framed transport sends 64-bit storage words with 48 bytes per online message: carry `96+32p`, sign `96+32p`, GRank `96+16n`, routing `96+16n`; total `384+64p+32n` wire bytes. Offline bytes are **measured serialized bundle bytes plus two 8-byte length prefixes**, split into score materials, GRank package, rank mask/DPF keys and envelope metadata. Local calls per party: `2p` score uCMP / `4p` score DCF Eval, `C(n,2)` ranking uCMP / `2C(n,2)` ranking DCF Eval, `nK` native DPF Eval, `n(K-1)` output ring additions and `n` local parity extractions. No online field multiplication, no masked combine and no new output key.

This F1 quantity is a **standard bit-mask specialization**, not Theorem 4.2's field-valued general payload cost. The earlier H1 field-core logical formula and ratio remain scoped to that separate core. Rank routing still uses project `Z_(2^r)` rather than paper `Z_n` for non-powers of two. General arbitrary secret record ring→field conversion and field-core→XOR-bit conversion remain open capabilities; they are not prerequisites for this bit-only standard API. `AUTHOR_EXACT=NOT_PROVEN`; M5 overall remains `IN PROGRESS` until independent F2/G3 acceptance.
